# Руководство разработчика (Beta-1.0)

## Запуск и устройство кода

В Windows используйте Python 3.12: `pip install -r requirements.txt`, затем `python -m wtpoligon`. Точка входа проходит через `wtpoligon/__main__.py` и `gui/app.py`. Последний находит игру (или принимает `--game`), допускает источник-датамайн (`--datamine`) и явную папку записи (`--target`), загружает индекс техники и открывает окно Qt. Датамайн без `--target` доступен только для чтения.

| Пакет или модуль | Задача |
|---|---|
| `game/` | Чтение установленных VROMFS и BLK через `source.py`, сохранение типов BLK, индекс техники, поиск названий, изображения, логи и модификации. |
| `gui/` | Шесть страниц и `window.py`; в `texts.py` — русские подсказки; `workers.py` выносит тяжёлую работу из цикла Qt. |
| `scenarios/` | Модель сценария, каталог целей, автоподбор по БР, проверка и фрагменты миссии. |
| `ammo/` | Каталог орудий и снарядов, модель боекомплекта, баллистика, проверка и копии изменённых боеприпасов. |
| `stats.py` | Поля характеристик по видам техники, стоковые значения, статусы проверки, границы и правки. |
| `loadout.py` | Пилоны, штатные пресеты, каталог оружия, своя подвеска, расчёт массы и проверка. |
| `build.py`, `edits.py`, `mission.py` | План файлов миссии/BLK/CSV из моделей шагов, типизированные правки и сверка результата с источником. |
| `install.py` | Ограничение путей, запись своих файлов, манифесты SHA-256, бэкапы и откат. |
| `logs.py` | Архив с манифестами программы и свежими логами игры. |

## Поток данных

`game.source` открывает архивы установленной игры → `game.index` создаёт кэшируемый индекс техники; каталоги подвески, боеприпасов и сценариев проходят по ссылкам игры → страницы Qt хранят модели выбранной машины → `build.stock_plan()` создаёт план пользовательской миссии и нужных локальных копий → `build.verify_plan()` сверяет созданные BLK с текущим стоковым деревом → `install.install()` пишет только допустимые пути и сохраняет хеши в манифесте применения → `install.uninstall()` удаляет неизменённые свои файлы или возвращает сохранённые оригиналы. Файл, изменённый после записи, остаётся. Архивы игры не переписываются. См. [переопределения BLK](../datamine/override.md), [пользовательские миссии](../datamine/user-missions.md) и [кэш](../datamine/caching.md).

В `gui/workers.py` используется `ProcessPoolExecutor` на два процесса с контекстом `spawn`. Рабочие процессы кэшируют читатели источника и собирают каталоги, характеристики, подвеску, поиск боеприпасов, подбор сценария, план проверки и логи. Страницы опрашивают результаты через `QTimer` и отбрасывают устаревшие ответы по номеру поколения при смене машины. Виджеты Qt остаются в главном потоке.

## Проверка и архив

Запускайте `python -m unittest discover -s tests`. `tools/ui_lag.py` измеряет отзывчивость окна при переходах и сборке каталогов. Поведение в установленной игре проверяйте по [docs/TESTING.md](../../TESTING.md), особенно для 📄. Для ZIP беты из подготовленной `.venv` запустите `.venv\Scripts\python tools\make_beta.py --name Beta-1.0`. Скрипт упакует переносной Python, зависимости, исходники, `run.bat` и уведомления в `dist/`; `.exe` он не создаёт.

## Правила проекта

Для каждой новой возможности найдите источник в данных игры, проверьте созданные файлы, затем испытайте результат в игре и лишь после этого ставьте **«проверено в игре»**. Непроверенные поля и сочетания отмечайте **«не проверено»** или **📄**; успешный разбор BLK не доказывает работу в бою. Не добавляйте в репозиторий и не распространяйте извлечённые файлы, иконки и архивы игры.
