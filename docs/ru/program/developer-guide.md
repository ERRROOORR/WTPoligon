# Руководство разработчика (2.0-beta)

## Запуск и устройство кода

Python 3.12 в Windows: `pip install -r requirements.txt`, затем `python -m wtpoligon`.

- Без аргументов точка входа проходит через `wtpoligon/__main__.py` и `gui/app.py`: тот находит игру (или берёт
  `--game`), принимает источник-датамайн (`--datamine`) и явную папку записи (`--target`), загружает индекс техники
  и открывает окно Qt.
- Датамайн без `--target` — только чтение.
- С командой (`list`, `mission`, `install`, `uninstall`, `status`, `check-all` и др.) `cli.py` делает ту же работу без
  окна.

| Пакет или модуль | Задача |
|---|---|
| `game/` | Чтение установленных VROMFS и BLK через `source.py`, типы значений BLK, индекс техники, поиск названий, изображения, логи игры, модификации. |
| `gui/` | Семь страниц шагов и `window.py`; `texts.py` — русские подсказки; `workers.py` выносит тяжёлую работу из цикла Qt. |
| `scenarios/`, `targets.py` | Модель сценария, каталог целей, подбор по БР, проверка, фрагменты миссии. |
| `support/` | Вызываемая техника: модель, каталог, сборка, проверка. |
| `ammo/` | Каталог орудий и снарядов, модель боекомплекта, баллистика, проверка, копии изменённых боеприпасов. |
| `stats.py` | Поля характеристик по видам техники, стоковые значения, статусы проверки, границы, правки. |
| `loadout.py` | Пилоны, штатные пресеты, каталог оружия, своя подвеска, самолёты-бомбы, расчёт массы, проверка. |
| `library.py` | «Моя техника»: сохранённые конфигурации в папке данных программы. |
| `hangar.py` | Отметки пользователя «есть в ангаре» (`hangar.json`). |
| `build.py`, `edits.py`, `mission.py` | Модели шагов → план файлов миссии/BLK/CSV, типизированные правки, сверка результата с источником. |
| `install.py` | Ограничение путей, запись своих файлов, манифесты SHA-256, бэкапы, откат. |
| `applog.py` | Журнал программы `%LOCALAPPDATA%\WTPoligon5\logs\wtpoligon.log` (по 2 МБ, 3 старые копии): запуск, запись и откат, ошибки проверки и сборки, необработанные исключения, долгие шаги. |
| `logs.py` | Архив для разбора: манифесты программы, журнал программы, свежие логи игры. |

## Поток данных

1. `game.source` открывает архивы установленной игры.
2. `game.index` создаёт кэшируемый индекс техники; каталоги подвески, боеприпасов, вызываемой техники и сценариев
   идут по ссылкам игры.
3. Страницы Qt хранят модели выбранной машины.
4. `build.stock_plan()` создаёт план файлов: пользовательскую миссию и нужные локальные копии.
5. `build.verify_plan()` сверяет созданные BLK с текущим стоковым деревом.
6. `install.install()` пишет только допустимые пути и сохраняет хеши в манифесте применения.
7. `install.uninstall()` удаляет неизменённые свои файлы или возвращает сохранённые оригиналы. Файл, изменённый после
   записи, остаётся.

Архивы игры не переписываются. См. [переопределения BLK](../datamine/override.md),
[пользовательские миссии](../datamine/user-missions.md) и [кэш](../datamine/caching.md).

Фоновая работа:

- В `gui/workers.py` — `ProcessPoolExecutor` на два процесса с контекстом `spawn`.
- Рабочие процессы кэшируют читатели источника и собирают каталоги, характеристики, подвеску, поиск боеприпасов,
  подбор сценария, проверку и логи.
- Страницы опрашивают результаты через `QTimer` и отбрасывают устаревшие ответы по номеру поколения при смене машины.
- Виджеты Qt — только в главном потоке.

## Проверка и архив

- Тесты: `python -m unittest discover -s tests`.
- Вся игра: `python -m wtpoligon check-all` собирает миссию для всей техники.
- `tools/ui_lag.py` измеряет отзывчивость окна при переходах и сборке каталогов.
- Поведение в игре: [docs/TESTING.md](../../TESTING.md), в первую очередь пункты 📄.
- ZIP беты из подготовленной `.venv`: `.venv\Scripts\python tools\make_beta.py --name 2.0-beta`. Скрипт упаковывает
  переносной Python, зависимости, исходники, `run.bat` и уведомления в `dist/`; `.exe` не создаёт.

## Правила проекта

- Для каждой возможности: источник в данных игры → проверка созданных файлов → проверка в игре → только потом
  **«проверено в игре»**.
- Непроверенные поля и сочетания помечаются **«не проверено»** или **📄**; успешный разбор BLK не доказывает работу
  в бою.
- Извлечённые файлы, иконки и архивы игры в репозиторий не добавляются и не распространяются.
