# `include` и `@override`

Локальный текстовый BLK может начинаться с `include "#/develop/gameBase/gameData/.../original.blk"`, после чего к стоковому дереву применяются правки. Включение вставляется в указанном месте; следующие строки обрабатываются по порядку. Обычные объявления добавляются, даже если имя уже существует. `@override` заменяет существующий параметр или правит существующий блок. Исходный архив игры не меняется.

| Путь или директива | Смысл | Единицы | Статус |
|---|---|---|---|
| Первая строка `include "#/develop/gameBase/gameData/..."` | Включить стоковый BLK в локальную копию | — | Verified in game |
| `"@override:name":r=value` | Заменить существующий параметр того же типа | исходные единицы | Verified in game |
| `"@override:block"{...}` | Править первый блок с данным именем | — | Verified in game |
| `"@override:name[n]"` | Выбрать n-е одноимённое вхождение, начиная с 1 | индекс | Verified in game |
| `@delete`, `@delete-all`, `@clone-last` | Удаление и клонирование по правилам парсера BLK | — | Unverified (in files only) |

Перед записью проверьте точное стоковое дерево: отсутствующая цель и несовпадение типов попадают в лог, а правка пропускается. Обычный дубликат может оставить в работе первое значение. Обновление игры может сместить индексы вхождений. Пишите по одному параметру в строке, сохраняйте тип, применяйте правки к дереву установленной игры и сверяйте итоговое значение до установки.

Миссия, машина и проверенные копии оружия перечитываются при загрузке миссии; перезапуск игры для них не нужен. Новые копии пресетов тоже подхватываются во время работы игры, а повторная правка уже использованного пресета следует из логов и не проверялась отдельно в игре. CSV локализации читается при запуске игры.
