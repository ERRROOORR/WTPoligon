# BLK: бинарный и текстовый формат

BLK — дерево именованных блоков и типизированных параметров. Бинарный файл внутри VROMFS может хранить имена локально (FAT) либо ссылаться на общую таблицу `?nm` архива (SLIM); бывают варианты со zstd и словарём. Текстовый BLK используется для локальных копий и миссий. Сохраняйте порядок и повторяющиеся имена: правка может адресовать конкретное вхождение.

| Путь или поле | Смысл | Единицы | Статус |
|---|---|---|---|
| Вид бинарного BLK `1`, `3`, `4`, `5` | Наблюдавшиеся FAT, SLIM и сжатые SLIM | код | Unverified (in files only) |
| `?nm` / локальные имена BLK | Общая или собственная таблица имён | — | Unverified (in files only) |
| `name:t="text"` | Строка | — | Unverified (in files only) |
| `name:i`, `name:i64`, `name:b` | Целое 32/64 бита, логическое (`yes`/`no`) | значение | Unverified (in files only) |
| `name:r`, `name:c`, `name:m` | Вещественное число, цвет, матрица | значение | Unverified (in files only) |
| `name:p2/p3/p4`, `name:ip2/ip3/ip4` | Векторы вещественных или целых значений | значение | Unverified (in files only) |

В текстовом BLK заключайте в кавычки имена со специальными символами, пишите один параметр в строке и экранируйте строки через `~` (`~"`, `~~`, `~n`). Обратная косая черта не экранирует строку. При замене сохраняйте тип параметра. Разбор бинарного формата и круговая запись текста сверены на исследованных файлах; это само по себе не доказывает влияние поля в игре.
# Бинарные варианты и правила текста

| Форма или тип | Где находится | Смысл / единицы | Статус | Наблюдение |
|---|---|---|---|---|
| Вид `1`, `3`, `4`, `5` | Первый байт бинарного BLK | FAT, SLIM, SLIM+zstd, SLIM+zstd со словарём | Unverified (in files only) | Все четыре встретились в изученных архивах. Вид `2` реализован по описанию, но там не найден. |
| Счётчик собственных имён / `?nm` | Тело BLK / служебная запись VROMFS | ULEB; нуль означает общую карту NameMap | Unverified (in files only) | Для имён SLIM нужен содержащий архив. |
| `t`, `i`, `i64`, `b`, `r` | Текстовые параметры | Строка, целое 32/64 бит, флаг, float32 | Unverified (in files only) | При override сохраняют тип; float32 нужно записывать без потери точности. |
| `c`, `m`, `p2/p3/p4`, `ip2/ip3/ip4` | Текстовые параметры | Цвет, матрица, вещественные и целочисленные векторы | Unverified (in files only) | В бинарном цвете байты идут B,G,R,A; `ip4` содержит четыре целых. |
| Повтор имени блока или параметра | Любое дерево BLK | Упорядоченный повтор | Unverified (in files only) | Номера одноимённых объектов в override начинаются с единицы. Обычный словарь теряет повторы. |
| Имя в кавычках / экранирование `~` | Текстовый BLK | Синтаксис имени и строки | Unverified (in files only) | Имена с пробелом, косой чертой, двоеточием или `@` заключают в кавычки; кавычку в строке экранируют `~"`. |

Текстовое значение заканчивается на `;`, переводе строки, `}` или `//`. Пишите один параметр в строке. Короткие коды типов: `t i b c r m p2 p3 p4 ip2 ip3 ip4 i64`. Логические значения также принимают `on/off`, `true/false`, `1/0`; генератор может единообразно писать `yes/no`. Обратная косая черта перед кавычкой не экранирует её. В бинарных именах могут быть байты вне UTF-8; при чтении их нельзя терять.

Изученный бинарный парсер прошёл круговую проверку на 31 647 файлах. Сравнение с другим текстовым выводом выявило расхождения в кавычках необычных имён, порядке каналов цвета и пунктуации `ip4`. Текстовый вывод полезен для сверки, но не заменяет дерево с типами.
